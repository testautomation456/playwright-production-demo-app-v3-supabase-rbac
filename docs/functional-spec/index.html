Functional & Data Flow Specification

Playwright Production Demo App — V3

A role-based Node.js/Express reference application backed by Supabase Postgres, built to give automation engineers a realistic surface — auth, CRUD, reporting, audit logging — to write Playwright UI and API tests against.

Version 3.0.0 Runtime Node.js + Express 4 Database Supabase Postgres Doc date 2026-08-26

01 Overview

The application is a single Express server (server.js) that serves both a static, vanilla-JS front end (public/pages/*.html) and a JSON REST API under /api/*. There is no client framework and no server-side templating — pages are static HTML shells that call the API via fetch() and render results client-side (public/js/app.js).

Authorization is stateless: on login the server issues a signed JWT containing the user's role, which the browser stores in localStorage and replays as a Bearer token on every subsequent request. The server never holds session state — each request is independently authenticated and authorized against the token.

Why this shape matters for testing: because every screen is driven by an equivalent API call, the app is deliberately testable at two layers that must agree — the UI layer (Playwright browser tests) and the API layer (Playwright request tests) — which is the app's stated purpose per tests/ui and tests/api.

04 Authentication Flow

Login is the only unauthenticated write. Every other API route is gated by requireAuth, and privileged routes are further gated by requireRole(...).

sequenceDiagram
  participant B as Browser (login.html)
  participant S as Express (server.js)
  participant A as auth.js
  participant DB as Postgres · app_users

  B->>S: POST /api/auth/login { username, password }
  S->>DB: select * from app_users where lower(email)=lower($1) and status='active'
  DB-->>S: user row (incl. password_hash)
  S->>S: bcrypt.compare(password, password_hash)
  alt credentials valid
    S->>A: signUser(user)
    A-->>S: JWT { sub, role, email, name }, expires in 8h
    S->>DB: insert into audit_logs (action='LOGIN')
    S-->>B: 200 { token, user }
    B->>B: localStorage.setItem(rbacDemoToken, rbacDemoUser)
    B->>S: subsequent requests carry Authorization: Bearer <token>
    S->>A: requireAuth() verifies signature + expiry
    A-->>S: req.user = { sub, role, email, name }
    S->>A: requireRole(...allowed) checks req.user.role
  else invalid credentials
    S-->>B: 401 { error: "Invalid username or password" }
  end

Fig. 2 — Login & per-request authorization. No server-side session store; the JWT itself is the session.

Token & guard reference

Token claims
{ sub: user.id, role, email, name }
Expiry
8 hours (expiresIn: '8h')
Transport
Authorization: Bearer <token> header, attached by public/js/app.js → api()
Client storage
localStorage keys rbacDemoToken, rbacDemoUser
requireAuth
Verifies signature/expiry; rejects with 401 on missing or invalid token
requireRole(...roles)
Rejects with 403 if req.user.role is not in the allowed list

05 Roles & Access Control

Three fixed roles, enforced identically at the page level (client-side redirect) and the API level (requireRole middleware) — the API is the real boundary; the UI check only avoids showing a screen the API would reject.

admin

Full access to every page and API route, including user management, disabling accounts, and deleting customers.

manager

Operational access: customers, products, orders, reports. No user administration, no customer deletion.

user

Self-service only: own profile, own orders (assigned_user_id = self), read-only on customers/products.

06 Data Model

Five tables in the public Postgres schema (scripts/schema.sql). All primary keys are UUIDs except audit_logs, which is a bigserial append log.

09 Order Lifecycle

Orders move through a fixed status set enforced by a Postgres check constraint on orders.status; transitions are performed via PUT /api/orders/:id/status (admin/manager only).

  Processing --> Shipped
  Shipped --> Completed
  New --> Cancelled
  Processing --> Cancelled
  Completed --> [*]
  Cancelled --> [*]
